# 《程序构造力》写作原则

## 核心原则

1. **不写概念百科** — 不要写成"什么是 UI 库""什么是状态库"。要写成：页面结构出现后，需要路由构造件承接页面流转。状态结构出现后，需要状态构造件承接状态拥有和订阅更新。
2. **不用问题清单** — 避免"是否……""有没有……"句式。改成动作句：先列出领域对象，再标记字段，接着抽取用户动作。
3. **每章必须有可交付产物** — 每章结尾必须给出：本章产物、从业者输出、可复用模板、贯穿案例中的本章结果。
4. **所有章节服务主线** — 主线只有一条：需求场景 → 程序结构建模 → 构造件选择 → 胶水代码连接 → 最小可运行系统。基础语法和表达单元必须降级为"低阶材料与局部表达"，不能成为最高主线。
5. **前端库必须进入体系** — 前端库不是零散工具，而是结构承接物。组件库承接界面结构，路由库承接页面流转结构，状态库承接状态结构。
6. **后端库也必须进入体系** — 后端也有构造件，只是不是视觉组件，而是 API、权限、数据访问、任务、缓存、日志、观测、测试和部署结构的承接物。
7. **最终目标不是生成代码，而是生成系统** — 最后停在：一个有前端、后端、结构规格、构造件选择、胶水代码、运行命令、测试路径的最小可运行系统。

## 章节产出

每章至少包含：
- 核心转换映射（输入→输出表格）
- 完整例子（基于 Task Manager 贯穿案例）
- 本章产物（可复用模板/检查表/映射表）
- 从业者输出（读者学完能做什么）

## 全书语言

- 示例语言：Python（后端），TypeScript/React 示例在前端章出现
- 正文用中文，关键术语首次出现括号补充英文
- 代码块、配置、文件名、API、工具名保留英文原样
- 英文术语全书一致

## 章节结构

```
## 本章问题
## 背景：为什么这章重要
## 核心内容（### 子小节展开）
## 例子与实践
## 小结（连接下一章）
## 本章产物
## 从业者输出
```

## 禁用清单

- ❌ 不以"本章介绍……"开头
- ❌ 不写概念百科式罗列
- ❌ 不用问题清单（所有判断改为可执行动作、转换步骤、结构产物）
- ❌ 不过度深入边缘细节（保持聚焦）
