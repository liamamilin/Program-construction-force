# 《程序构造力》

## 副标题

从需求结构到构造件组装，把想法变成可运行系统

---

# 全书主线

需求场景
→ 程序结构建模
→ 构造件选择
→ 胶水代码连接
→ 最小可运行系统

本书只解决一个核心问题：

拿到一个需求后，如何把它拆成程序可以承接的结构，如何判断哪些部分自己写、哪些部分交给库、框架、组件或脚手架，最后如何组装成一个最小可运行系统。

本书不是教读者从语法堆出程序，而是教读者把需求转化为结构，把结构映射到代码、库、框架、组件和脚手架，再组装成可运行系统。

本章定义全书起点：需求场景层。

拿到一个需求后，第一件事不是选框架、不是搭项目壳、不是写代码，而是搞清楚程序要解决什么问题、谁使用它、用户做什么、系统接收什么输入、输出什么结果、哪些失败必须处理。

本章核心内容：

* 需求场景层的定义
* 需求场景的六要素：问题、用户、动作、输入、输出、失败
* 需求场景和代码材料的区别
* 需求场景到程序结构建模的入口

* 需求场景六要素检查表
* 需求场景描述模板

# Part 2：支撑模块：基础代码材料与程序表达

注意：基础代码材料与程序表达不是主构造链的一层，而是贯穿所有层的支撑模块。它帮助读者理解代码如何表达局部含义，但不决定程序的整体结构。

## 第 3 章：基础语法只是低阶代码材料

本章定义基础语法层。

基础语法不是程序本身，而是程序表达的低阶材料。变量、条件、循环、函数、类、列表、字典、异常、模块、文件读写，都只是代码材料。

注意：低阶材料是必要的起点，但不是全书的顶峰。本书的最终目标是需求→结构→构造件→系统，语法材料只是贯穿全程的工具。

本章核心内容：

* 基础语法层的定义
* 代码材料的六类分类
* 数据材料、控制材料、抽象材料、调用材料、外部交互材料、失败处理材料
* 语法材料在全书体系中的位置——低阶但必要

本章产物：

* 基础语法层总表
* 语法材料分类表
* 语法材料到表达单元的入口图

## 第 4 章：基础语法如何进入程序表达

本章建立基础语法到程序表达单元的转换。

`for + if` → 筛选，`dict` → 映射，`class + fields` → 表示，`if + raise` → 验证，`try/except` → 失败处理。

本章核心内容：

* 常见语法组合的程序含义
* 表达单元是语法和结构之间的中间层

本章产物：

## 第 5 章：程序表达单元：数据、集合、判断、运行、失败与反馈

本章定义五类程序表达单元。

程序表达单元是基础语法组合出来的稳定程序含义。它不是单个语法，也不是完整程序，而是位于语法和结构之间的局部表达。

五类：

* 数据表示表达：表示、字段、关系、集合、配置、结果
* 集合处理表达：遍历、筛选、转换、查找、映射、分组、排序、聚合
* 判断与规则表达：条件、规则、验证、权限、限制、触发
* 运行推进表达：状态、状态变化、动作、流程
* 失败与交付表达：失败、恢复、输出、反馈

本章产物：

* 程序表达单元定义
* 五类表达单元总表
* 表达单元到语法形式映射表

# Part 3：程序结构建模层

## 第 6 章：程序结构建模是什么

本章定义程序结构建模层。

程序结构建模不是把表达单元整理成更大的代码说明，而是把需求中的稳定结构抽取出来。

它产出的是结构规格包，由五类结构和一个横向切面组成：

五类结构：
1. 领域结构（Domain Structure）
2. 交互结构（Interaction Structure）
3. 状态结构（State Structure）
4. 边界结构（Boundary Structure）
5. 组合结构（Composition Structure）

横向切面：
约束与可靠性切面（Constraint & Reliability Slice）

本章核心内容：

* 程序结构建模的定义
* 结构规格包概述（五类结构 + 一个横向切面）
* 结构建模和代码表达的区别
* 结构建模层在全书体系中的位置

本章产物：

* 程序结构建模层定义
* 结构规格包总览表
* 结构建模层地图

## 第 7 章：领域结构：对象、字段、关系、生命周期

本章构建领域结构——程序中的事物、特征和关联。

领域结构包括：

* 对象卡片：每个领域的核心事物
* 字段说明：每个对象的属性类型和约束
* 对象关系：对象之间的关联
* 生命周期：对象从创建到销毁经历的阶段
* 领域约束：字段约束、关系约束、生命周期约束、领域不变量

注意：配置结构移到边界结构。结果结构移到边界结构。

本章核心内容：

* 需求对象如何变成对象卡片
* 字段如何变成字段说明
* 关系如何变成对象关系
* 对象的阶段如何变成生命周期
* 约束不是独立的结构，而是领域结构上的切面

本章产物：

* 对象卡片模板
* 字段说明表

## 第 8 章：交互结构与状态结构

本章构建交互结构和状态结构——程序中的动作、事件、状态和流程。

交互结构包括：

* 用户动作：用户能做什么
* 系统事件：系统能做什么
* 命令：动作和事件的输入规格
* 查询：数据读取规格
* 交互流程：动作的先后顺序和条件

状态结构包括：

* 状态拥有者：什么对象有状态
* 业务状态：领域相关的阶段
* UI 状态：界面相关状态
* 请求状态：网络请求的阶段
* 缓存状态：缓存数据的寿命
* 异步任务状态：后台任务的阶段
* 状态转移：合法状态变化
* 反馈动作：操作后的用户反馈

本章核心映射：

* UI 局部状态 → useState / ref
* 全局共享状态 → Redux / Zustand / Pinia

* 表单状态 → React Hook Form
* 路由状态 → React Router / Vue Router

本章产物：

## 第 9 章：边界结构、组合结构与约束可靠性切面

本章构建边界结构、组合结构，以及作为横向切面的约束与可靠性。

边界结构包括：

* API 边界
* UI 输入边界
* 数据库边界
* 文件边界
* 外部服务边界
* 消息队列边界
* 输入输出契约
* 错误响应契约

组合结构包括：

* 组件树
* 页面结构
* 模块结构
* 服务结构
* 适配器结构
* 依赖结构

约束与可靠性切面是横向切面，贯穿所有五类结构：

* 领域结构 → 字段验证、关系一致性、生命周期测试
* 交互结构 → 权限、前置条件、确认动作、用例测试
* 状态结构 → 合法转移、非法转移保护、并发冲突测试
* 边界结构 → 输入校验、输出格式、错误码、超时、重试
* 组合结构 → 依赖替换、mock、集成测试、观测

# Part 4：构造件层

## 第 10 章：构造件是什么：库、框架、组件、SDK 与脚手架

本章定义构造件层。

构造件是已经实现好的结构承接物。它不是基础语法，也不是完整程序，而是可以被选择、配置、组合和适配的高阶代码资产。

传统教学认为程序 = 自己写的代码。现实是：程序 = 自写代码 + 构造件 + 胶水代码。

构造件分类：

* UI 构造件
* 状态构造件
* 数据请求构造件
* 验证构造件
* 路由构造件
* 后端入口构造件
* 数据访问构造件
* 权限构造件
* 任务构造件
* 缓存构造件
* 观测构造件
* 测试构造件
* 脚手架构造件

本章核心表：结构问题 → 可选构造件 → 需要补的胶水代码

本章产物：

* 构造件定义
* 构造件分类总表
* 结构到构造件映射表
* 贯穿案例：Task Manager 的构造件选择

## 第 13 章：脚手架：把结构规格变成项目壳

脚手架是一组结构规格的默认落地形态。它不解决具体业务，但解决目录、入口、配置、依赖、构建、测试、运行和扩展位置。

前端脚手架示例：Vite + React 项目壳

选择脚手架的决策：当结构规格中的大部分结构有稳定构造件承接时，脚手架是最快的起点。
